# SeekStorm C# SDK audit — 2026-10-13

This review covers SDK commit `01c282c` plus the lifecycle and shard-count fixes currently present as uncommitted changes. It checks the managed API against the pinned SeekStorm 3.4.1 crate. The review did not modify the SDK implementation.

## Overall assessment

The package and native integration work has improved substantially: the NuGet package now carries platform-specific native libraries; external-vector indexing has an explicit schema path; filters are validated; and the 3.4.1 Union facet panic has a targeted workaround. The native handle lifecycle and default shard count are being corrected in the current working tree after a real Windows OOM failure.

The SDK is not ready to publish yet. There are still correctness problems in public request/response types, silent fallback for malformed options, and incomplete error reporting for asynchronous indexing. The current 0.2.1 CI run failed on both Windows RIDs before packing, so there is no passing end-to-end package-consumer/AOT gate for this candidate. Neither 0.2.0 nor 0.2.1 was published.

## Highest-priority outstanding issues

### P1 — Setting `Length = 0` can delete documents instead of deleting none

`SearchRequest.Length` is omitted from JSON when it equals its default value (`WhenWritingDefault`) at [SearchRequest.cs:33-35](../../src/SeekStorm.Bindings/Models/SearchRequest.cs:33). The FFI then substitutes `10` when `length` is absent at [lib.rs:490-491](../../src/seekstorm-ffi/src/lib.rs:490). SeekStorm documents length zero as count-only behavior; it does not mean “use the default page size.”

The destructive case is `DeleteByQueryRequest.Length`: it is also omitted when zero at [IndexModels.cs:174-176](../../src/SeekStorm.Bindings/Models/IndexModels.cs:174), while the FFI substitutes length 10 at [lib.rs:356-357](../../src/seekstorm-ffi/src/lib.rs:356), then deletes those hits. A caller explicitly setting `Length = 0` can therefore delete ten matching documents. Preserve explicit zero in serialization or validate/reject zero for delete-by-query. Add regression tests for both search and deletion.

### P1 — Indexing and commit can report success after shard work fails

The FFI returns `{"status":"indexed"}` after calling upstream `index_document` at [lib.rs:273-291](../../src/seekstorm-ffi/src/lib.rs:273). In SeekStorm 3.4.1, `IndexArc::index_document` spawns a detached shard task and drops its join handle (`index.rs:5300-5319`); `index_documents` merely loops through these submissions (`index.rs:5279-5285`). A worker panic is not returned to this FFI call.

The commit implementation waits for shard work, but logs `JoinSet` errors and returns `()` (`commit.rs:156-165, 168-199`). The FFI consequently returns `committed` even if a shard commit task failed. The new panic guard only covers the immediate FFI task; it cannot observe detached worker failures. Treat these methods as queued/submitted unless the SDK can track task results, or patch/wrap the engine so indexing and commit failures reach callers. At minimum, document this limitation and add a failure-oriented test; the current status strings overstate the guarantee.

### P1 — Suggestions response model does not match upstream JSON

SeekStorm 3.4.1 defines search suggestions as `Vec<String>` (`search.rs:211-212`). The managed result expects `List<Suggestion>` with `term`, `distance`, and `count` at [SearchRequest.cs:191-195, 219-229](../../src/SeekStorm.Bindings/Models/SearchRequest.cs:191). When the engine returns any suggestions, JSON deserialization can throw instead of returning search results. The current typo test does not require a nonempty suggestion at [SeekStormClientTests.cs:334-351](../../tests/SeekStorm.Bindings.Tests/SeekStormClientTests.cs:334). Match the upstream string shape or explicitly transform it, and make a deterministic test that returns at least one suggestion.

### P1 — `Highlights` and `DistanceFields` are accepted but ignored

`SearchRequest` exposes and serializes these properties at [SearchRequest.cs:84-96](../../src/SeekStorm.Bindings/Models/SearchRequest.cs:84), but `seekstorm_search` never reads either field ([lib.rs:433-543](../../src/seekstorm-ffi/src/lib.rs:433)). The pinned crate’s `Search::search` signature has no highlight or distance arguments (`search.rs:1138-1154`); those options belong to upstream `GetDocumentRequest` (`index.rs:423-438`). The current FFI getter accepts only a document ID and passes empty field/highlight/distance settings (`lib.rs:574-593`). Requests appear successful while returning no requested results. Implement a typed get-document request path, or remove/reject these unsupported search options until it exists.

### P1 — Invalid enum and numeric values silently change query semantics

The FFI maps unknown `search_mode` values to lexical, unknown query types to Intersection, and unknown result types to TopkCount ([lib.rs:718-749](../../src/seekstorm-ffi/src/lib.rs:718)). Unknown query-rewriting mode becomes SearchOnly ([lib.rs:751-778](../../src/seekstorm-ffi/src/lib.rs:751)). Numeric fields similarly use `unwrap_or` defaults: malformed/negative offsets, lengths, and thresholds can become plausible default searches. A spelling mistake such as `SearchMode = "Vectro"` therefore silently executes a different query instead of reporting invalid input. Validate supplied values and reject unknown names/types. In particular, preserve the distinction between absent `length` and an explicit zero.

### P2 — InferenceConfig is not a usable typed configuration

`IndexMeta.Inference` accepts `JsonObject?` at [IndexModels.cs:92-97](../../src/SeekStorm.Bindings/Models/IndexModels.cs:92), so callers cannot assign the advertised `InferenceConfig` class. That class serializes flat fields (`model`, `precision`, `vector_similarity`, etc.) at [IndexModels.cs:208-233](../../src/SeekStorm.Bindings/Models/IndexModels.cs:208), while upstream `Inference` is a tagged enum such as `{"Model2Vec":{"model":...,"chunk_size":...,"quantization":...}}` or `{"External":...}` (`seekstorm-3.4.1/src/vector.rs:281-318`). The new `SearchConfiguration.ExternalVectors` path covers external vectors, but built-in model inference remains inaccessible through the typed helper and its documented shape is incompatible. Replace the stale helper/property with typed tagged variants, or remove it and document the exact JSON requirement.

### P2 — Configuration limits still need bounds

The new `ShardCount` default of one is a necessary fix, but the FFI accepts any positive `u64` and casts it to `usize` at [lib.rs:164-172](../../src/seekstorm-ffi/src/lib.rs:164); the managed API only checks positive values. A very large value can still request enough per-shard buffers to exhaust memory. `segmentBits` is also passed directly as an unsigned native value at [SeekStormClient.cs:41, 64](../../src/SeekStorm.Bindings/SeekStormClient.cs:41), with no range validation. Bound both values before allocation and return a clear argument error.

## Lifecycle and Windows OOM findings

The real CI failure was a Windows test-host crash while allocating a 400,000,000-byte shard buffer. SeekStorm’s default shard count is based on machine parallelism; each shard reserves roughly 400 MB for the posting buffer. On GitHub’s Windows runners, creating the default number of shards exhausted available memory. The run logs show the failure in `dotnet test` for `win-x64` and `win-arm64` after the native build and smoke test passed.

The current uncommitted changes address the root causes:

- `IndexMeta.ShardCount` defaults to one and documents the per-shard reservation ([IndexModels.cs:10-14](../../src/SeekStorm.Bindings/Models/IndexModels.cs:10)). The FFI forwards the configured count to `create_index` ([lib.rs:164-188](../../src/seekstorm-ffi/src/lib.rs:164)).
- The old close path only dropped the boxed `IndexArc`. SeekStorm stores root `Arc<Index>` references inside shards, creating a root/shard ownership cycle; dropping the handle alone neither breaks the cycle nor reliably commits/clears shard references. The working tree now calls upstream `Close::close()` in `close_handle` ([lib.rs:237-247](../../src/seekstorm-ffi/src/lib.rs:237)), and C# uses a checked close operation ([SeekStormClient.cs:457-480](../../src/SeekStorm.Bindings/SeekStormClient.cs:457)). A new test verifies pending documents survive Dispose and reopen ([SeekStormClientTests.cs](../../tests/SeekStorm.Bindings.Tests/SeekStormClientTests.cs)).

These are uncommitted and have not yet passed the six-RID CI gate. In addition, upstream `Close::close` contains `unwrap`/`expect` calls in shard mmap reset (`seekstorm-3.4.1/src/index.rs:5068-5087`); wrapping the call in `catch_unwind` is important because the old void close export otherwise risks unwinding across `extern "C"`. The current working tree does wrap the close body and reports checked-close errors. However, upstream commit still swallows shard task errors, so checked close can report success after a failed commit task; this shares the P1 commit-observability limitation above.

## Fixes verified in committed code

The following work is present in commits through `01c282c` and has meaningful regression coverage:

- **Native NuGet packaging:** runtime files are staged under all six RIDs and the package verifier checks managed assembly plus native assets. The workflow now has a real isolated package consumer and NativeAOT publish/run gate; earlier steps no longer use `continue-on-error`.
- **External vector setup:** `SchemaField.IndexVector` and `SearchConfiguration.ExternalVectors` express the correct external-vector schema (`Json` field with `index_vector=true`, and the tagged `External` inference object). Strict query-vector parsing rejects non-arrays, nonnumeric/nonfinite entries, empty vectors, and external-index dimension mismatches.
- **Filter safety:** malformed, unknown, wrong-type, or disabled facet filters are rejected instead of silently widening a query. Vector/hybrid facet filtering intersects the complete ranked candidate set with lexical facet eligibility before pagination, and explicitly refuses indexes above the 100,000-document bound or unsupported facet aggregation combinations.
- **SeekStorm 3.4.1 Union panic workaround:** `align_facets` adds a zero-length internal facet when a filtered Union query has no query-facet slot, avoiding the engine’s `query_facets[i]` panic; the synthetic facet is removed from response facets. Regression coverage includes Union filtering and asserts the internal key is not leaked.
- **Panic containment:** fallible FFI operations use `catch_unwind` and convert engine panics to SDK errors. A Rust unit test exercises that guard.
- **Large UTF-8 inputs:** the managed interop now uses pooled, null-terminated buffers rather than document-sized `stackalloc` buffers.

The local smoke test exercises external-vector ranking, hybrid/filter behavior, upsert/delete/reopen, invalid filters, and Union filtering. The package workflow is much stronger than the original package-only build.

## Verification and release status

GitHub Actions run `38406908064` for tag `v0.2.1` completed with a failure. Native build, panic test, Release build, smoke test, and .NET tests passed on `linux-x64`, `linux-arm64`, `osx-arm64`, and `osx-x64`. The `win-x64` and `win-arm64` .NET test jobs aborted with the 400 MB allocation failure. Because those jobs failed, `pack`, the six-platform package-consumer/AOT jobs, and publishing were skipped. This is direct evidence that the native binaries and project-reference tests worked on four RIDs, but it is not evidence that the produced NuGet package passed consumer or AOT validation.

The `ShardCount=1` and checked-close lifecycle fixes are only in the current working tree. Rerun the complete workflow after committing them; require all six native build/test jobs, package verification, and all six package consumer/AOT jobs to pass before publishing. The previous 0.2.0 publish was cancelled, and 0.2.1 has not been published.

## Recommended order

1. Fix the zero-length serialization/deletion behavior and add a test proving `DeleteByQueryRequest.Length = 0` cannot delete records.
2. Make suggestions deserialize correctly; make all exposed but unsupported highlight/distance options explicit.
3. Surface or clearly qualify background indexing/commit failures; do not signal durable success when the engine cannot report it.
4. Reject malformed enums and numeric fields; bound shard count and segment bits.
5. Replace the incompatible inference helper with a typed upstream-compatible model.
6. Rerun all six RIDs and the package consumer/AOT gate after the current lifecycle/shard changes; only then publish.

## Resolution for the 0.2.2 candidate

The findings above record the audit history. The candidate now preserves explicit
zero-length requests, matches native string suggestions, rejects unsupported
highlight/distance options, validates query enum/numeric fields, and serializes
Model2Vec/external-vector configurations with the correct tagged shape. Invalid
updates are checked before deletion, including missing/deleted IDs and repeated
IDs. Unknown document keys and null typed fields fail explicitly.

Native allocation is bounded to the embedded **one-shard** contract and segment
bits fixed at 11. This avoids CPU-count-based memory growth and preserves reliable pending
stored-field verification. Raw-handle operations serialize as a whole; raw close
requires exclusive caller ownership. Null create/open outputs fail before native
allocation. Failed managed index switches preserve the original usable handle;
reopening its path is idempotent and recreating it is rejected.

The optional upstream spelling dictionary is deliberately **unsupported**, rejected
before allocation. The failed frequent-word experiment is not shipped. There is no
engine patch, vendor copy or registry edit. Opening old spelling/multi-shard indexes
also fails explicitly. The smoke runner fails on background panic/task-failure logs.
This resolves the release blocker by excluding a broken optional capability, not by
claiming that the upstream defect is fixed.

Commit verifies expected counts and stored-field fingerprints, but is not a complete
transactional/error-propagation layer over all upstream auxiliary structures.
Schemas without stored fields have count-only checks. This limit is documented.
Local Release build, 25 .NET tests and pipeline smoke passed without background
native panics. The final Rust guard/boundary tests and six-RID/package-consumer CI
must pass before the package is published. Built-in model download/inference remains
an upstream operational dependency; configuration shape is tested, not live remote
model availability.


The attempted 12-bit boundary test exposed another upstream constraint:
`open_index` reconstructs indexes with 11 segment bits, and a 12-bit index panicked
on reopening. The binding therefore now requires exactly **11** at creation,
rejects other values before allocation, and tests commit/reopen at that required
configuration. This also prevents excessive segment-map allocation. No engine
change was made. Create/open share schema/inference validation, including rejecting
Json-vector fields for non-External inference, and open validates the persisted
one-shard layout before the engine allocates buffers. CI pins Python 3.12 for the
background-failure-aware smoke runner.


## 0.2.3 package gate correction

Candidate 0.2.2 passed all six native build/smoke/test jobs and the managed/NativeAOT
package consumer on both Linux and both macOS RIDs. Both Windows package consumers
failed during restore: the public NuGet URL was interpreted as a project-relative
Windows file path (`NU1301`). Publication was skipped. Candidate 0.2.3 keeps the
same binding implementation and replaces repeated CLI source arguments with a
portable generated NuGet configuration containing an absolute local feed and the
literal HTTPS feed URL. No engine change is involved. The full gate is rerun.
